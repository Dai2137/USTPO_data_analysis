# 週次MTGレポート — 2026-09-29

## ストーリー

### 1. 提案するベンチマークの有用性と新規性

既存の細粒度ベンチマークは、1つの上位カテゴリ（鳥、車、航空機など）の中での識別を測る。複数の上位カテゴリを含むもの（Oxford-IIIT Pets、iNaturalist）や、複数の細粒度データセットを混ぜ、上位カテゴリを与えずに推論する設定（Erudite FGVC）もあるが、上位カテゴリ同士は見た目で容易に区別でき（Erudite では鳥と車の区別が 99.3%）、難しさは上位カテゴリの中での区別がメインである。現実世界では、上位カテゴリが異なっていても形状が似ている物体の組み合わせが存在し、これらを区別する際に、物体の上位カテゴリが前提として分からないことも考えられるが、このように上位カテゴリをまたいで形状が似ている状況は、既存の細粒度ベンチマークでは想定していない。そこで、上位カテゴリが広い範囲にわたり、かつ、その上位カテゴリは未知である（つまり、母集団が特定の上位カテゴリに限定されない）ことを前提にしたベンチマークを提案する。

### 2. 細粒度画像認識（FGVC）の精度を上げる先行研究の分類

画像に物体が1つ写っていて、その下位カテゴリ名を当てる細粒度認識（CUB、Stanford Cars、FGVC-Aircraft などの文脈）の手法を、次の木で分類した。


```text
A. 推論に LLM を用いない
   A-1. 分類ヘッドを学習する（CNN・ViT）
        API-Net、From Coarse to Fine-Grained OSR（全体のみ）、CAL（局所のみ）、
        RA-CNN、DCAL、Multi-level Attention-enhanced、Dual-TR、IELT、TransFG、Erudite（全体と局所・配分固定）、
        MGE-CNN、FG-MoE、HEF（全体と局所・配分がサンプルごと。ゲートや閾値をテストと同じカテゴリで学習）
   A-2. CLIP の埋め込みの類似度で分類する
        A-TPT、FineR（全体のみ）、FAIR（局所のみ）、microCLIP、LAGO（全体と局所・配分固定）
B. 推論に LLM を用いる
   B-1. 手法の核が、上位カテゴリやカテゴリが所与の有限な集合であることを前提とする
        全体のみ：Finedefics、ReFine-RFT、TARA、SARE、RAR、UniFGVC、VR-RAG、
                  Zero-Shot FG Classification Using LVLMs、AutoSEP、FruitEnsemble、CascadeVLM、nlg2choice
        全体と局所・配分がサンプルごと・局所も選ぶ：ToolFG
   B-2. 手法の核が、上位カテゴリやカテゴリが所与の有限な集合であることを前提としない
        全体のみ：Fine-R1、DiVE-k、SpeciaRL
        全体と局所・配分がサンプルごと・局所も選ぶ：該当なし ← 提案手法
```


### 3. 提案ベンチマークに適用できるのは B-2

提案ベンチマークは、上位カテゴリが未知で、母集団が特定の上位カテゴリに限定されない。そのため、所与の有限な集合を前提とする手法は、そのままでは適用できない。

- **A-1**：テストと同じカテゴリで学習しないと使えない。
- **A-2 と B-1**：候補のカテゴリの一覧や上位カテゴリを与えることが前提になっている。

**適用できるのは B-2 の手法**（Fine-R1、DiVE-k、SpeciaRL）である。3本とも MLLM を強化学習で事後学習する手法で、答えの引き出し方や推論の仕方を改善する。ただし、**3本とも画像全体だけを入力しており、画像のどこを見るかは扱っていない。** B-2 の中で、全体と局所の配分と局所の選び方をサンプルごとに決める手法はない。ここに提案手法を置く。

## MTG での FB

**全体の評価**：問題設定はまとまった。基本の方向はこれで良い。まずは既存手法でどこまで精度が出るかを出すところから進める。

**1. B-2 の3本は自由記述に対応しているか**

- 既存研究の評価は、学習データとテストデータが分かれたデータセット（鳥、車など）で、カテゴリが限定された選択肢の画像分類として行われている。
- 手法は LLM なので自由記述にも対応できるはずだが、まだ精読できていない。今後やることの1で確認する。

**2. 自由記述にしたときの評価（採点）の仕方**

- 完全一致の採点は厳しすぎるので、ある程度の答えのぶれを認める必要がある。どこまで認めるかが難しい。
- 先行研究では、答えと正解を埋め込みモデルで埋め込み、類似度で測っている。
- LLM が上位概念に逃げる（具体的な名前ではなく大まかな名前を答える）問題を指摘している研究もある。

**3. カテゴリ間の類似度を事前に確認する（重要）**

- 意匠を使うのでカテゴリが非常に細かい。細かくなったときの肝は、**類似度で見るとかなり近い2つのカテゴリを、ちゃんと区別できるか**にある。
- そのため、類似度で採点する前に、**カテゴリ（製品名）間の類似度の近さを確認しておく**べき。「これ以上近くなければ正解と認めない」という線が問題なく引けるかを見る。類似度を見るだけならすぐできる。
- 自分の対応：形状が似ているもの（例：四角い物体）だけを集め、その中で製品名の意味がどれくらい散らばっているかを確認する。形状が似ていても、意味が似ている場合と似ていない場合があるはず。

**4. 自由記述ではなく、全カテゴリからの選択にする案**

- カテゴリ（製品名）の粒度は「iPhone」ではなく「スマートフォン」くらいで、全部で数千種類ある。
- 数千から1つを選ぶ形なら、選択肢があっても難しさは自由記述とほぼ同じで、「上位カテゴリが未知」という設定から外れないのではないか。
- 自由記述と似たようなものなので、どちらにしても、まずカテゴリ間の類似度がどうなっているかを一度見ておく。

**FB を受けて追加でやること**

- 製品名（カテゴリ）間の類似度を計算し、正解と認める類似度の線が引けるかを確認する。
- 形状が似ている図面の集合の中で、製品名の意味の散らばりを確認する。
- 評価の形式（自由記述か、数千の全カテゴリからの選択か）は、類似度の確認の結果を見て決める。
- 既存手法（B-2 の3本など）で、提案ベンチでの精度を出す。
