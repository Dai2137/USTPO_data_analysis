# 週次MTGレポート — 2026-07-02

## 背景・目標

デザイナーや審査官が本当に知りたいのは、タイトルの一致ではなく、**特定の機能・用途・使用文脈を持つ意匠がどのような形状として実現されているか**という形状と機能の対応関係である。現行のタイトル検索にも画像類似検索にも、この問いに直接答える手段はない。

**→ 機能と形状の対応関係を埋め込み空間に学習させ、機能文をクエリとして形状画像を検索するシステムを実現したい。**

## 1. 今週やったこと

### 前提：COrAL アーキテクチャと学習方法

詳細は前回レポート（2026-06-18）参照。以下に要点を再掲する。

#### 表現の 3 成分分解

COrAL は画像とテキストのペアから 3 種類の表現を同時に学習する。

| 成分 | 内容 |
| --- | --- |
| **Redundant（共有）** | 画像・テキスト双方に共通する情報（製品カテゴリ・概念） |
| **Unique（固有）** | 各モダリティにしか存在しない情報（画像：幾何構造、テキスト：機能文脈） |
| **Synergistic（相乗）** | 単独モダリティでは表現できず、両方を統合して初めて現れる情報（形状↔機能の連動性） |

```
入力ペア (画像 v, テキスト t)
    ├─ FusionTransformer（画像パッチ + テキストトークンを結合して Attention）
    │       → z_fused  (B, 512)  ← Shared/Synergistic
    ├─ 画像 Unique パス: Linear + AttentionPooling → MLP
    │       → z_img_uniq (B, 512)
    └─ テキスト Unique パス: Linear + AttentionPooling → MLP
            → z_txt_uniq (B, 512)
```

#### 損失関数

$$\mathcal{L} = \mathcal{L}_{\text{shared}} + (\mathcal{L}_{\text{img}} + \mathcal{L}_{\text{txt}}) + (\mathcal{L}_{\text{ortho\_mods}} + \mathcal{L}_{\text{ortho\_img}} + \mathcal{L}_{\text{ortho\_txt}})$$

| 損失項 | 内容 | 役割 |
| --- | --- | --- |
| $\mathcal{L}_{\text{shared}}$ | InfoNCE$(z_{\text{fused}}^{(1)}, z_{\text{fused}}^{(2)})$ | Shared/Synergistic 空間の対照学習 |
| $\mathcal{L}_{\text{img}}$ | InfoNCE$(z_{\text{img\_uniq}}^{(1)}, z_{\text{img\_uniq}}^{(2)})$ | 画像 Unique 空間の対照学習 |
| $\mathcal{L}_{\text{txt}}$ | InfoNCE$(z_{\text{txt\_uniq}}^{(1)}, z_{\text{txt\_uniq}}^{(2)})$ | テキスト Unique 空間の対照学習 |
| $\mathcal{L}_{\text{ortho\_mods}}$ | CosineEmbeddingLoss$(z_{\text{img\_uniq}}, z_{\text{txt\_uniq}})$ | 画像 Unique とテキスト Unique を直交化（互いへの情報混入防止） |
| $\mathcal{L}_{\text{ortho\_img}}$ | CosineEmbeddingLoss$(z_{\text{img\_uniq}}, z_{\text{fused}})$ | 画像 Unique と Shared が重複しないよう直交化 |
| $\mathcal{L}_{\text{ortho\_txt}}$ | CosineEmbeddingLoss$(z_{\text{txt\_uniq}}, z_{\text{fused}})$ | テキスト Unique と Shared が重複しないよう直交化 |

各重みは $w_s = w_u = w_o = 1.0$、温度パラメータ $\tau = 0.1$。

#### 非対称マスキング（新規性の核心）

2 つの augmented view に**非対称**にモダリティをマスキングし、「テキストから形状を推論」「形状から機能を推論」させることで相乗情報を抽出する。

```
View 1: 画像を部分マスク + テキスト完全  → テキストから形状を推論
View 2: テキストを部分マスク + 画像完全  → 形状から機能を推論
```

マスキング比率はカリキュラム学習で段階増加（5% → 35% → 55% → 75%）。

### 1-1. COrAL 再現実装の定量評価

前回レポートで計画した評価を実施した。

**実験条件**

| 項目 | 内容 |
| --- | --- |
| 学習データ | IMPACT 2021 年（約 3 万件） |
| 評価データ | IMPACT 2022 年（33,541 件） |
| エンコーダ | DINOv2-base（画像）+ ModernBERT-base（テキスト）※初期凍結 |
| 学習条件 | bs=64, lr=1e-4, wd=1e-3, 100 エポック |
| タスク | `{title}. {caption}` テキスト → 意匠画像のクロスモーダル検索 |
| 表現 | shared（共有/相乗）ベクトルを使用 |

**評価結果**

| 評価プール | R@1 | R@5 | R@10 | MRR |
| --- | --- | --- | --- | --- |
| 全件（候補 33,541 件） | 0.012% | 0.051% | 0.092% | 0.083% |
| 同ロカルノクラス内（候補をクエリと同クラスに限定、平均 ≈1,048 件） | 0.19% | 0.84% | 1.65% | 0.98% |
| ランダムベースライン（全件）| 0.003% | 0.015% | 0.030% | — |
| ランダムベースライン（クラス内）| ≈0.10% | ≈0.48% | ≈0.95% | — |

**ロカルノフィルタあり/なしの比較**

全件プールと同ロカルノクラス内プールの差（約 16 倍の R@1 向上）は、プールサイズの縮小（33,541 件 → 約 1,000 件）によるもので、本質的な性能向上を意味しない。各プールのランダムベースラインを基準にすると：

| | 全件プール | 同クラス内プール |
| --- | --- | --- |
| モデル R@1 | 0.012% | 0.19% |
| ランダム R@1 | 0.003% | ≈0.10% |
| **ランダム比** | **約 4 倍** | **約 2 倍** |

全件プールではランダム比 4 倍（クラスをまたいだ粗い識別は学習できている）なのに対し、同クラス内ではランダム比 2 倍にとどまる。**ロカルノ分類で絞り込んでも、同カテゴリ内での意匠の区別はほぼ機能しておらず、むしろカテゴリ内識別はクロスカテゴリ識別より苦手**であることを示している。

### 1-2. なぜ性能が出ないのか：caption の識別力調査

「モデルの問題か、データの問題か」を切り分けるため、IMPACT の caption（AI 生成テキスト）が同タイトルの意匠間で意匠固有の情報を持っているかを確認した。

以下は同一カテゴリ（靴）の 2 件の caption である。

**D943889**
> 画像には白い輪郭で描かれた靴が示されています。靴は足を保護し、快適性を提供する履物です。用途や好みに応じて、さまざまなデザイン、素材、サイズがあり、歩行やランニング、スポーツなど幅広い目的で使用されます。また、ファッションアイテムとしても利用されます。

**D943891**
> 画像には白い輪郭で描かれた靴が示されています。靴は足を保護・支持し、さまざまな地形や気象条件から足を守る役割があります。一般に革、ゴム、合成素材などで作られ、歩行やランニング、スポーツなどさまざまな用途に使用されます。

2 件の caption は完全に言い換えの関係にあり、**どちらを読んでも「靴である」という以上の情報が得られない**。アッパーの形状・ソールのパターン・締結方式・ヒールの有無など、2 件の意匠を視覚的に区別する要素は一切記述されていない。

caption は「その製品のタイトルと一般的な情報」しか語らず、「この意匠固有の設計思想」を捉えていない。モデルがこのテキストをクエリとして学習しても、同カテゴリ内の識別シグナルを受け取れないため、同クラス内のランダム比が 2 倍に留まることは必然である。


一方で，意匠固有の設計思想をテキストが捉えているcaption（＝製品のタイトル以上の情報量を持つ）も存在する．
以下は同一カテゴリ（靴）の 2 件の caption である。
**D943873**
> 画像は白黒で描かれたハイヒールです。この靴は、足を支え保護するとともに、スタイリッシュなデザインによって着用者の外観を引き立てます。フォーマルな場面やパーティー、ファッションアイテムとしてさまざまな場面で使用されます。

**D943876**
> 画像は白黒で描かれた単層ソールの靴で、黄色のアウトソールパッチと対照的な色合いのアッパーを備えています。この靴は、カジュアルで快適な履物と考えられます。単層ソール構造により柔軟で快適な履き心地を実現しています。黄色のアウトソールパッチはデザイン上のアクセントであるとともに、ブランドやモデルを識別する役割を持つ場合があります。また、コントラストのあるアッパーは、異なる素材や色を組み合わせることで独特な外観を生み出しています。

### 1-3. 根本課題の特定

**ユースケース**

目指す検索システムの問いは：

> **「（機能）を持った（製品名）はどういう（形状）をしているか？」**

デザイナーや審査官が本当に知りたいのは、タイトルの一致ではなく、**特定の機能・用途・使用文脈を持つ意匠がどのような形状として実現されているか**という形状と機能の対応関係である。現行のタイトル検索にも画像類似検索にも、この問いに直接答える手段はない。

**→ 機能と形状の対応関係を埋め込み空間に学習させ、機能文をクエリとして形状画像を検索するシステムを実現したい。**

**課題の構造**

```
根本課題: 形状と機能の対応関係が示されている（機能文, 画像）学習ペアが少ない
    → COrAL が意匠固有の視覚差分を学習できない
```

IMPACT の caption のほとんどは ロカルノ分類/タイトル レベルであるので，情報量は製品のタイトルだけにすぎず，captionとして意味をなさない．意匠画像のテキスト文として意味を持つのは `title` と機能文を記述しているごく一部の caption に限られる。


**リサーチクエスチョン（暫定）**

> **「L3 レベルの機能文ペアが少数しかない状況で、同カテゴリ内の意匠画像を区別できる表現をどう学習するか？」**

## 2. 今後やること

### 次のステップ：L3 caption 絞り込み（VLM によるフィルタ）

**目的:** IMPACT の caption から「意匠固有の機能文（L3）」だけを抽出し、高品質な学習ペアを確保する。

**判定基準:**

以下の 3 条件をすべて満たす caption を L3（keep）とする。

1. **意匠固有の形状・機能の記述がある** — 製品カテゴリの一般的な説明ではなく、この意匠の具体的な形状・構造・用途が記述されている
2. **「同じ製品名でも、設計思想（形状と機能の対応関係）は意匠ごとに異なる」を体現している** — caption を読むだけで、他の同タイトル意匠とは異なる設計思想が伝わる
3. **操作的定義：ある意匠画像の caption が、同タイトルの他の意匠画像には当てはまらない** — VLM に「この caption はこの別の画像にも当てはまるか？」と問い、No と答えられる

**手順:**

1. 対象意匠 D（title: T）の caption C を取得
2. 同タイトル T の他の意匠 D' を N 件サンプリング
3. ローカル VLM に「この caption C はこの画像 D' に当てはまるか？（Y/N）」を問う
4. D には当てはまるが D' には当てはまらない → **L3（keep）**
5. D にも D' にも当てはまる → L2（discard）

**出力:** 二値ラベル（keep / discard）付きの caption リスト

**使用モデル:** ローカル VLM

**意義:** L3 と確認された caption のみを COrAL の学習ペアとして使用することで、少数だが高品質な訓練信号を確保する。
