### 1-2. COrAL を選んだロジック

#### 現行の検索システムへの問題提起

既存の意匠検索は「**製品名・ロカルノ分類によるタイトル検索**」が主流である。しかしこれには本質的な限界がある。

**同じ製品名でも、設計思想（形状と機能の対応関係）は意匠ごとに異なる。**

たとえば "Toothbrush" というタイトルでヒットする意匠は多数存在するが、そのうち「幼児向けに太いグリップで握りやすく設計されたもの」と「電動ブラシのヘッドを交換しやすくした構造のもの」は、外観も機能も本質的に異なる設計思想を持っている。タイトルで検索してもこの違いは取り出せない。

意匠は「**外観（形状）と機能が連動するように設計される**」ものであり、形状の違いはそのまま機能・用途の違いを反映しているはずである。

##### 実際の検索ニーズ：「（機能）を持った（製品名）はどういう（形状）をしているか？」

デザイナーや審査官が本当に知りたいのは、タイトルの一致ではなく、**特定の機能・用途・使用文脈を持つ意匠がどのような形状として実現されているか**という形状と機能の対応関係である。現行のタイトル検索にも画像類似検索にも、この問いに直接答える手段はない。

**→ 機能と形状の対応関係を埋め込み空間に学習させ、機能文をクエリとして形状画像を検索するシステムを実現したい。**

- **クエリ**：機能文（機能・用途・使用文脈を含むテキスト。形状記述あり/なし両対応）
- **データベース**：画像のみ（全意匠にテキスト付与は莫大コスト）

→ **テキストクエリ → 画像 DB のクロスモーダル検索**を実現したい。

#### 意匠データの本質的な性質

意匠は「**外観（形状）と機能が連動するように設計される**」という本質的な性質を持つ。

| モダリティ | 共有情報 | 固有情報 |
| --- | --- | --- |
| 画像 | 製品の概念・カテゴリ | 幾何構造・形状の細部 |
| テキスト | 製品の概念・カテゴリ | 機能・用途の文脈 |

ここで重要なのは、「**形状の固有情報**」と「**機能の固有情報**」は完全に独立ではないという点である。意匠においては形が機能を暗示し、機能が形を規定する――この関係を**相乗（Synergistic）情報**として明示的に学習することが、意匠クロスモーダル検索の精度向上に寄与すると考える。

#### 各手法の問題点と COrAL が適している理由

| 手法 | 問題点 |
| --- | --- |
| CLIP 式単純アライメント | 画像とテキストを「似すぎる」ベクトルに揃え、モダリティ固有の情報（形状・機能文脈）が失われる |
| DeCUR（2 成分分解） | 固有成分を完全直交化するため、形状と機能の連動性（相乗情報）が捨てられる。またテキストモダリティを直接想定していない |
| **COrAL（3 成分分解）** | Redundant（共有）・Unique（固有）・**Synergistic（相乗）** を分けて学習。非対称マスキングにより「画像から機能を推論する」「テキストから形状を推論する」能力を獲得し、意匠の形状↔機能の連動性を表現空間に埋め込める |

**意匠でやりたいこと（形状と機能の相乗効果を学習したい）に最も適合する手法が COrAL** と判断した。

### 1-3. COrAL の詳細

#### 表現の 3 成分分解

```text
入力ペア (画像 v, テキスト t)
    │
    ├─ FusionTransformer（画像パッチ + テキストトークン を結合して Attention）
    │       ↓
    │   Shared/Synergistic ベクトル  z_fused  (768-dim → MLP → 512-dim)
    │
    ├─ 画像ユニークパス: Linear(768→384) + AttentionPooling → MLP → 512-dim
    │       ↓  z_img_uniq
    │
    └─ テキストユニークパス: Linear(768→384) + AttentionPooling → MLP → 512-dim
            ↓  z_txt_uniq
```

#### 損失関数

$$\mathcal{L}_{\text{total}} = w_s \cdot \mathcal{L}_{\text{shared}} + w_u \cdot (\mathcal{L}_{\text{img}} + \mathcal{L}_{\text{txt}}) + w_o \cdot (\mathcal{L}_{\text{ortho\_mods}} + \mathcal{L}_{\text{ortho\_img}} + \mathcal{L}_{\text{ortho\_txt}})$$

| 損失項 | 内容 | 役割 |
| --- | --- | --- |
| $\mathcal{L}_{\text{shared}}$ | InfoNCE( $z_{\text{fused}}^{(1)}, z_{\text{fused}}^{(2)}$ ) | Shared/Synergistic 空間の対照学習 |
| $\mathcal{L}_{\text{img}}$ | InfoNCE( $z_{\text{img\_uniq}}^{(1)}, z_{\text{img\_uniq}}^{(2)}$ ) | 画像固有空間の対照学習 |
| $\mathcal{L}_{\text{txt}}$ | InfoNCE( $z_{\text{txt\_uniq}}^{(1)}, z_{\text{txt\_uniq}}^{(2)}$ ) | テキスト固有空間の対照学習 |
| $\mathcal{L}_{\text{ortho\_mods}}$ | CosineEmbeddingLoss( $z_{\text{img\_uniq}}, z_{\text{txt\_uniq}}$ ) | 画像固有とテキスト固有を直交化（混入防止） |
| $\mathcal{L}_{\text{ortho\_img}}$ | CosineEmbeddingLoss( $z_{\text{img\_uniq}}, z_{\text{fused}}$ ) | 画像固有と共有が重複しないよう直交化 |
| $\mathcal{L}_{\text{ortho\_txt}}$ | CosineEmbeddingLoss( $z_{\text{txt\_uniq}}, z_{\text{fused}}$ ) | テキスト固有と共有が重複しないよう直交化 |

実装では $w_s = w_u = w_o = 1.0$、温度パラメータ $\tau = 0.1$。

#### 非対称マスキング（新規性の核心）

学習の 2 つの augmented view に**非対称にモダリティをマスキング**し、一方のモダリティから他方の情報を推論させることで相乗情報を抽出する。

```text
View 1: 画像を部分マスク   + テキスト完全（→ テキストから形状を推論）
View 2: テキストを部分マスク + 画像完全   （→ 形状から機能を推論）
```

マスキング比率はカリキュラム学習的に段階増加：

| エポック | マスキング比率 |
| --- | --- |
| 0〜24 | 5% |
| 25〜49 | 35% |
| 50〜74 | 55% |
| 75〜 | 75% |

#### 先行手法との比較（新規性まとめ）

| 観点 | CLIP | DeCUR | COrAL |
| --- | --- | --- | --- |
| 成分分解 | なし（単一アライメント） | 2 成分（共有・固有） | **3 成分（共有・固有・相乗）** |
| 固有成分の独立化 | — | 完全直交化 | 直交化しつつ相乗で連動性を保持 |
| 相乗情報の抽出 | — | — | **非対称マスキング** |
| テキスト＋画像への直接適用 | ○ | △（主に同種センサー） | **○（画像+テキスト想定）** |

### 1-4. 再現実験

#### 目的

COrAL を意匠特許データ（IMPACT）に適用し、3 成分（共有・固有・相乗）分解が意匠クロスモーダル検索で有効に機能するか検証する。

#### 実験条件

**データセット**

| 項目 | 内容 |
| --- | --- |
| データ | IMPACT design patent dataset（2007〜2022 年、約 44 万件） |
| 使用テキスト | `{title}. {caption}`（IMPACT の AI 生成キャプションをそのまま使用） |
| 使用画像 | 表紙図面（`D00000.TIF`） |
| 画像前処理 | 下 8% クロップ（"Fig." ラベル除去）、縦横比 >2.0 → 左半分、<0.45 → 上半分に切り出し |
| データ拡張（画像） | RandomResizedCrop(224, scale=0.4〜1.0) + RandomHorizontalFlip + CLIP 正規化 |
| データ拡張（テキスト） | Word dropout（p=0.10） |

**エンコーダ・Embedding フロー**

```text
画像
  CLIPPatchEncoder (openai/clip-vit-base-patch32)
    → パッチトークン列 (B, 50, 768)

テキスト
  BERTTokenEncoder (bert-base-uncased, max_length=128)
    → トークン埋め込み列 (B, 128, 768)

共有/相乗パス
  FusionTransformer（1 layer, 8 heads）over [img_patches; txt_tokens]
    → (B, 768)
    → MLP(768 → 1024 → 1024 → 512)
    → z_fused (B, 512)

固有パス（画像・テキスト各独立）
  Linear(768→768) + LayerNorm + GELU + Linear(768→384) [トークンごと]
    + AttentionPooling
    → (B, 384)
    → MLP(384 → 1024 → 1024 → 512)
    → z_uniq (B, 512)
```

**学習条件**

| パラメータ | 値 |
| --- | --- |
| batch_size | 64 |
| optimizer | AdamW (lr=1e-4, weight_decay=1e-3) |
| max_epochs | 100 |
| エンコーダ | 初期凍結（`--unfreeze 0`） |
| 非対称マスキング | 有効（比率 5%→35%→55%→75% のカリキュラム） |
| GPU | 1 枚（accelerator="auto"） |
