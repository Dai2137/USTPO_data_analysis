# Staging Drive-hosted images to local Colab disk before bulk reading

## Why

Colab's Drive mount (`/content/drive/MyDrive/...`) is a network filesystem. Opening thousands of individual files through it — whether via a DataLoader loop, `Image.open()` in a loop, or even just listing a large directory tree — pays per-file/per-call network latency and is slow enough to matter at this project's scale (IMPACT has 20k-35k+ patents per year). This was confirmed directly: enumerating a Drive-mounted folder tree with `ls`/`find` from a local Windows shell stalled for several minutes on a single year's image folder. The fix used throughout this project is to **copy the whole zip archive to local Colab disk once, then extract from the local copy** — a single large sequential file copy is fast even over the network, and all subsequent reads then hit local SSD.

## The pattern (adapted from `train_qwen_lora_title_2021_2022_multiview.ipynb`)

1. **Copy the zip, not individual files.** `shutil.copy2(drive_zip_path, local_zip_path)` where `local_zip_path` is under `/content/...` (ephemeral local disk, not the Drive mount). This is the expensive-but-one-time step (~2-4 minutes for a ~12GB zip in this project's experience).
2. **Extract only what's needed, flattened.** Don't blindly extract every member — compute the set of filenames actually required (e.g. from a filtered dataframe's `file_names` column) and iterate `zipfile.ZipFile(local_zip).namelist()`, extracting a member only if `Path(member).name` is in the needed set. Extract using just the basename (`Path(member).name`) into a flat local directory, ignoring the zip's internal path structure — this project's zips have inconsistent internal layouts across years, so matching by filename rather than by path is the robust approach.
3. **Idempotency via filename-set diffing, not counting.** Before extracting, compute `existing = {p.name for p in local_dir.glob('*.TIF')}` and `missing = needed - existing`; skip extraction entirely if `missing` is empty. Comparing set contents (not just counts) matters because a coincidental count match (e.g. after changing a sampling parameter and rerunning) would otherwise hide a real content mismatch.
4. **Delete the local zip copy after extracting** (`local_zip.unlink()`) to reclaim disk space — only the extracted files need to persist for the rest of the session.
5. **This staged directory is session-local and ephemeral** — it lives under `/content/...`, not the Drive mount, so it does not survive a Colab disconnect/reconnect and must be rebuilt each fresh session (which is fine — that's the ~minutes-scale cost being traded for fast in-session reads). Do not confuse this with the Drive-persisted checkpoint files from `.claude/skills/resumable-batch-jobs/SKILL.md` — those two mechanisms solve different problems (staging is a per-session I/O speed-up; checkpointing is cross-session crash recovery) and are often needed together in the same notebook.

## When to reach for the pre-extracted flat folder instead

Some years/subsets in this project already have a pre-extracted flat folder on Drive (e.g. `data/IMPACT/{year}_D00001/` containing cover-image-only TIFFs directly, no zip). If the full per-patent file set you need is already covered by such a pre-extracted folder, staging can target that folder's corresponding zip (`{year}_D00001.zip`) the same way — still stage-then-extract-locally rather than reading the pre-extracted Drive folder directly in a tight per-file loop, since the underlying Drive-mount slowness applies equally to pre-extracted individual files as it does to zip members.
