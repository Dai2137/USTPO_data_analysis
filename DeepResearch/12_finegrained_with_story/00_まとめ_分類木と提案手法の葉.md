- **元資料**：同じフォルダの Deep Research の報告（`claude.md`・`gemini.md`、推論に LLM を用いる手法に絞った `claude_plus.md`・`gemini_plus.md`・`gpt_plus.md`、B-2 に絞った `claude_b2.md`・`gemini_b2.md`・`gpt_b2.md`）と、B-2 の6本の参考文献。挙がった論文を取り寄せ、全文を読んで分類した。判定はすべて PDF の原文に基づく。報告の判定は根拠に使っていない（特に Gemini の報告は、論文名の取り違えや定義と合わない判定が多い）。
- **PDF の置き場所**：`論文/論文PDF/FGVC分類木/`。この分類木と同じフォルダ構成にしてある（11章）。

## 1. 結論

- **推論に LLM を用いる FGVC 手法（20本）のうち、手法の核が「上位カテゴリやカテゴリが所与の有限な集合であること」を前提としないのは6本（Fine-R1、DiVE-k、SpeciaRL、VL-Taxon、SelfSynthX、KFRA）。** 5本は画像全体だけを入力し、局所も使う KFRA は全体と局所を並べて LMM に渡すだけ（配分固定）。
- **提案手法の葉（B-2・全体と局所の配分がサンプルごと・局所も選ぶ）は空。**
- **局所の選び方と配分をサンプルごとに変える、推論に LLM を用いる手法は ToolFG（arXiv 2606.02518）だけで、B-1 に入る。** 入力で上位カテゴリと候補の選択肢を与え（"This is an image containing a bird. Please identify the species of the bird in the image from the below options."）、上位カテゴリ専用の部位ツール（`bird_*`）を使う。新規性は、見るべき部位が分かった上で、外部ツールで測って具体的な判断基準を得ること（5.4 節）。
- **推論に LLM を用いない側（A）の全体と局所の手法**：
  - 同じ型（配分も局所の選び方もサンプルごと）は、MGE-CNN（ICCV 2019）、FG-MoE（Pattern Recognition 2026）、HEF（AAAI 2023）の3本で、すべて A-1。どれもゲートや閾値を、テストと同じカテゴリのラベル付きデータで学習し、学習したカテゴリしか扱えない。
  - 局所をサンプルごとに選ぶ LAGO（A-2）は、CLIP の埋め込みの類似度で分類し、配分は固定。
- **新規性の書き方**：母集団が限定されない（上位カテゴリが未知で、候補の一覧もない）細粒度認識で、全体と局所の配分と局所の選択をサンプルごとに決める手法は、ない。
- **ベンチの形式は自由記述にする。** 選択肢を与えると、選択肢から上位カテゴリが推測でき、「上位カテゴリが未知」という前提がぶれるため。
- **比較実験**：
  - 基本のベースラインは「全体だけを LLM に入れる」。B の既存手法20本のうち18本はこの形。
  - B-2 の6本は、候補の一覧なしで動くので、自由記述の意匠ベンチに載る。ただし SelfSynthX は学習データの合成にクラスごとの概念リストが要り、KFRA は Web 画像検索に依存する。
  - **外部ツールを含む手法は、木の別枠に置き、ベースラインから外す（2026-10-02 決定）。** 提案手法は End-to-End で解くことを追求するため。該当するのは KFRA（Google Lens の Web 画像検索、Wikipedia）と ToolFG（部位の計測ツール）。B-2 のベースラインは残りの5本（SpeciaRL、Fine-R1、DiVE-k、VL-Taxon、SelfSynthX）にする。2本とも関連研究では扱い、本来の位置（KFRA は B-2・全体と局所・配分固定、ToolFG は B-1・配分がサンプルごと・局所も選ぶ）は別枠の中に書き残す（4.3 節）。
  - 加えて、LAGO（A-2、配分固定）、MGE-CNN（A-1、意匠ベンチの学習用分割で学習し、未知のカテゴリでの差を見る）を入れる。A の手法を自由記述のベンチでどう動かすかは、別に決める。
- **「適応的な重み付けは今後の課題」の引用**は microCLIP（Appendix E）だけ。

## 2. 論文のストーリーの順番

1. **ベンチの動機と提案**：「既存の細粒度ベンチマークは、1つの上位カテゴリ（鳥、車、航空機など）の中での識別を測る。複数の上位カテゴリを含むもの（Oxford-IIIT Pets、iNaturalist）や、複数の細粒度データセットを混ぜ、上位カテゴリを与えずに推論する設定（Erudite FGVC）もあるが、上位カテゴリ同士は見た目で容易に区別でき（Erudite では鳥と車の区別が 99.3%）、難しさは上位カテゴリの中での区別がメインである。現実世界では、上位カテゴリが異なっていても形状が似ている物体の組み合わせが存在し、これらを区別する際に、物体の上位カテゴリが前提として分からないことも考えられるが、このように上位カテゴリをまたいで形状が似ている状況は、既存の細粒度ベンチマークでは想定していない。そこで、上位カテゴリが広い範囲にわたり、かつ、その上位カテゴリは未知である（つまり、母集団が特定の上位カテゴリに限定されない）ことを前提にしたベンチマークを提案する。」（データセットの確認は8章）
2. **推論に LLM が必要になる**：母集団が限定されないので、推論には広い事前学習の知識が要る。そのため、推論に LLM を用いるかで手法を分ける（木の1段目）。
3. **所与の有限な集合を前提としない手法が要る**：上位カテゴリもカテゴリの一覧も与えられないので、手法の核がそれを前提としているかで分ける（木の B の2段目）。
4. **その中で、全体と局所をどう扱うかで分け、提案手法の葉が空いていることを示す**（4章）。

## 4. 分類木

### 4.1 軸

各階層は二択か四択にして、漏れと重複がないようにした（MECE）。

- **1段目（A／B）**：推論に LLM（MLLM・LVLM を含む）を用いるか。
  - 準備の段階（クラス記述の作成、カテゴリ名の発見）だけで LLM を使い、推論は CLIP の埋め込みの類似度などで分類する手法は A に入れる。
  - A は、分類の仕方で2つに分ける。A-1 は分類ヘッドを学習する（CNN・ViT。出力層が学習したカテゴリ数に固定される）。A-2 は CLIP の埋め込みの類似度で分類する（画像と各候補クラスの文を CLIP で埋め込み、コサイン類似度が最大のクラスを答える。候補のクラス名を差し替えられる）。A の下は、さらには分けない。
  - この軸にする理由：広い範囲のカテゴリにまたがり、しかも細かい部分を見ないと決まらない認識では、推論で LLM を使うことが必須になる（自分の考え）。
- **推論に LLM を用いる、とは**：テスト画像ごとに、推論の手順の中で LLM（MLLM・LVLM）を動かすこと。最終判定を LLM が出すかどうかは問わない（UniFGVC は、MLLM がテスト画像の記述を作り、最終判定は埋め込みの検索で行うが、B に入れる）。
- **B の2段目（B-1／B-2）**：手法の核が、上位カテゴリやカテゴリが所与の有限な集合であることを前提としているか。
  - この軸にする理由：意匠ベンチは自由記述で、上位カテゴリもカテゴリの一覧も与えない。そのため、それらを与えない設定で動くかが、手法を分ける一番の違いになる。
  - 「所与の有限な集合」の例：推論で与える候補の選択肢、全カテゴリの一覧（CLIP で全カテゴリにスコアを付ける、一覧から検索する、出力を一覧に限る）、カテゴリごとの見本・記述・テンプレート、分類階層、上位カテゴリの名前やそれ専用のツール。
  - 評価の設定ではなく仕組みで判定する。プロンプトの一語に上位カテゴリ名がある（"What is the name of the bird in the photo?"）だけで、外しても手法が成り立つものは、前提としていないと見なす。
  - 上位カテゴリは「鳥」、カテゴリは「鳥の種」（CUB のクラス名）のように、表現を厳密に分ける。
- **その下**：全体のみ ／ 局所のみ ／ 全体と局所・配分固定 ／ 全体と局所・配分がサンプルごと。配分がサンプルごとの下は、局所がランダムか、局所もサンプルごとに選ぶか。定義は 4.2 節のとおり。
- **枝にせず属性として扱うもの**：事後学習するか、推論の深さを変えるか（SARE、CascadeVLM、FruitEnsemble）、テスト時に適応するか（A-TPT）、未知の上位カテゴリに対応できるか、テストと同じ上位カテゴリの画像を手法の中で用いるか（その画像の使い方：見本として参照、テキストに変換、別のモデルを学習）。

### 4.2 全体と局所の軸の定義

**用語**

- **全体の表現**：画像全体を入力して得た表現。元画像（またはその縮小・反転などの拡張）を入れたときの [CLS] トークン、全パッチの平均、大域プーリング特徴、MLLM に元画像全体を入れたときの入力がこれに当たる。
- **局所の表現**：画像の一部の領域から得た表現で、全体の表現とは別の証拠として予測に使われるもの。次の2つを含む。
  - 画像を切り出した領域（クロップ）を入力して得た表現。
  - 特定の位置のパッチやトークン、領域の特徴を選び出して作った表現。
- **明示的に取り出す**：領域やトークンを選ぶ処理（切り出し、トークン選択、領域提案など）が、手法の手順として書かれていること。1回の順伝播の中で注意機構が暗黙にパッチを重み付けするだけのものは、局所を取り出したとは見なさない。
- **配分**：最終予測に対する、全体の表現と局所の表現の寄与の比。重み、ゲートの出力、閾値による起動・停止で表される。

**4つの葉**

1. **全体のみ**：最終予測を全体の表現だけから計算する。局所を明示的に取り出さない。
2. **局所のみ**：最終予測を局所の表現だけから計算する。全体の表現は、局所を選ぶため、または局所に重みを付けるためだけに使い、最終予測の項には入らない。
3. **全体と局所・配分固定**：最終予測に全体と局所の両方の表現が入り、両者の寄与の比を入力に応じて計算する仕組みがない。
   - 例：定数での平均・和、全サンプル共通の重み（学習で決まる重みを含む）、連結して固定の層に入れる、両方を並べて MLLM に入れる。
   - 注意機構の中で暗黙に混ざるだけのもの（TransFG、Dual-TR など）も、ここに入れる。
   - 局所の選び方がサンプルごとに変わっても、配分が固定ならここに入れる。
4. **全体と局所・配分がサンプルごと**：最終予測に全体と局所の両方の表現が入り、両者の寄与の比を入力ごとに明示的に計算する仕組みがある。
   - 例：入力から計算するゲート、確信度やエントロピーによる重み、不確かさの閾値による局所の起動（二値の切り替えもここに入れる）。
   - その下はさらに2つに分ける。
     - **局所はランダム**：局所の領域が画像の内容によらずに決まる（ランダムクロップ、固定の格子、中心クロップ）。
     - **局所もサンプルごとに選ぶ**：局所の領域を画像の内容に応じて決める（注意、顕著性、検出器、Grad-CAM、モデルの出力に基づく選択）。

**判定に迷う例**

- **CAL**：注意マップで特徴を重み付けてプーリングする。画像全体の大域特徴を別の項として使わないので「局所のみ」。
- **DCAL**：全体の自己注意の分類器と、高応答の局所との交差注意の分類器の確率を足す。和の重みは固定なので「配分固定」。
- **HEF**：不確かさが閾値を超えたときだけ局所の専門家を起動する。起動するかどうかが入力で変わるので「配分がサンプルごと」（二値）。
- **KFRA**：整合度が閾値 τ 未満のとき超解像して照合し直すが、閾値が切り替えるのは局所の照合のやり直しで、全体と局所の寄与の比ではない。全体と局所の証拠は並べて LMM に渡すだけなので「配分固定」。

### 4.4 補足

- **B 側の空白**：推論に LLM を用いる20本のうち18本は、画像全体だけを入力する。局所を使うのは ToolFG（B-1）と KFRA（B-2）だけ。ToolFG は画像の領域ではなく主にツールの計測値として局所を取り込み、KFRA は全体と局所を並べて渡すだけ。
- **Finer と FROW はベンチマークの論文として 8.2 節で扱う。** どちらも手法も提案しているが（Finer：属性を先に言わせるプロンプト AttrSeek と指示チューニング用データ、FROW：学習データの作り方）、主な貢献はベンチマーク。Finer の AttrSeek は、仕組みで見れば B-1（上位カテゴリの候補リストを与える段と、親カテゴリ名を次の段に注入する段が推論の核）。
- **上位カテゴリの扱い**：
  - 上位カテゴリを手法の中核で使うのは、HEF と From Coarse to Fine-Grained OSR（A）、ToolFG と TARA（B-1）。
  - 他の手法は、プロンプトや報酬の細部に上位カテゴリ名が出てくるだけで、外しても手法は成り立つ。
  - 上位カテゴリが限定されていることは、手法ではなくデータセットの性質として、8章で扱う。
- **意匠ベンチとの関係**：意匠ベンチは自由記述で、上位カテゴリも候補の一覧も与えない。
  - B-2 の手法は、そのまま載る。
  - B-1 の手法は、上位カテゴリや候補の一覧を与えないと動かない（または、与える前提で設計されている）。比べるなら、候補の一覧を与える別の設定を作る必要がある。
  - A-1 の手法は、テストのカテゴリで学習しないと使えない。
- **CaSED と Conti et al.（ICCV 2025）は木の外に置く**。語彙なしのオープンワールド分類で、FGVC 専用ではないため。ただし、動機を示す引用（上位語に逃げる現象、ドメインのヒントで答えが具体化すること）としては使う。
- **論文で使える主張**：B の既存手法の多くは、プロンプトに上位カテゴリ名を入れている（CascadeVLM "flower name"、nlg2choice "species of bird"、ToolFG、Finedefics の {SUPERCLASS}、Fine-R1、DiVE-k、SelfSynthX）。手法の核がそれを必要とするのではなく、「上位カテゴリを教えられる設定で性能が底上げされている」と書く。

## 5. 提案手法に近い仕組みを持つ手法

A-1 の3本（配分も局所の選び方もサンプルごと）、B-1 の ToolFG（同じく両方サンプルごと）、B-2 で唯一局所を使う KFRA。

### 5.1 MGE-CNN（ICCV 2019）：A-1

- 第1の専門家が元画像（全体）を見る。後続の専門家は、Grad-CAM で切り出した局所を見る。
  - "second expert is cropped based on attention map from previous input before zooming into the size of first input"
  - "In the train phase we use ground-truth label and during test time, we use predicted class label."
- "The gating network is then used to combine experts for making the final decision."
- → 配分も局所の選び方もサンプルごとに変わる。
- **提案手法との違い**：
  - ゲートと専門家を、テストと同じカテゴリのラベル付きデータで学習する。学習したカテゴリしか扱えない。
  - 局所の選び方は予測ラベルの Grad-CAM なので、学習済みのラベル空間に依存する。
  - 中核の仕組みは上位カテゴリを必要としない。意匠ベンチの学習用分割で学習し直せるので、ベースラインに入れる。

### 5.2 HEF（AAAI 2023）：A-1

- 専門家のカスケード："we input an image into expert 1 … Then we crop a discriminative subregion by using AOLM … and input it into expert 2 … multiple subregions with high response are further cropped out by using APPM"
- 不確かさで専門家を起動し、Dempster の規則で融合する。"expert 3 will be activated only when the fused uncertainty ufuse is greater than a threshold ε"
- **上位クラスのラベルを中核で使う**："FGIC aims to classify images into specific subordinate classes of a superclass"。上位クラスの証拠を、細粒度クラスに階層的に分解する。
- **提案手法との違い**：
  - テストと同じカテゴリで学習する閉集合の手法。
  - 上位カテゴリのラベルが仕組みの前提で、上位カテゴリが分からない設定では使えない。
  - 配分は閾値による段階的な切り替えで、連続的な比ではない。

### 5.3 FG-MoE（Pattern Recognition 2026）：A-1

- "A spatial-aware gating mechanism dynamically selects appropriate expert combinations for each input image."
- 専門家は、全体構造・領域の意味・局所の細部・テクスチャ・部位間の相互作用の5つ。画像は切り出さず、共通のマルチスケール特徴を入力に取る。
- **提案手法との違い**：
  - ゲートを、テストと同じカテゴリのラベル付きデータ（CUB・Dogs・NABirds）で学習する。学習したカテゴリしか扱えない。
  - 局所は画像の領域として選ばれず、特徴レベルで扱われる。

### 5.4 ToolFG（arXiv 2026、2606.02518）：B-1

- **仕組み**：MLLM（Qwen2.5-VL-7B）が推論の途中でツールを呼ぶ。"Each tool invocation is executed in a sandbox environment, and the execution result is returned to the MLLM in either textual or visual form, depending on the tool."
  - 例："the tool bird_color_histogram takes as input the name of a bird part (e.g., breast or wing) and returns the HSV and RGB color histograms of its pixels"
  - 推論の例：`bird_geometry("tail_to_bird")` → "the tail_height to bird_height is approximately 0.5"
- **ツールの作り方**（本文にあるのはこの1文だけ）："We design an MLLM-based automatic tool construction pipeline. To build the toolset, our pipeline first identifies a set of attributes that are useful for distinguishing highly similar subcategories, and then constructs invocable tools based on these attributes and task-specific knowledge from existing FGIC practices."
  - 属性を挙げるのは LLM ではなく MLLM（画像も見られる）。
  - "task-specific knowledge from existing FGIC practices" の出典として、導入で人間の専門家の測り方を示す文献（branson2010visual、wah2011multiclass、yang2018learning。いずれも CUB の部位を扱う研究）を引いている。
  - ツールは実行可能なプログラム（"tools are executable programs rather than differentiable model parameters"）。サンドボックスで実行し、単体テストに通ったものだけを採用する。
- **学習**：Gemini 2.5 Flash-Lite を教師に、MCTS で集めた正例と負例の推論の軌跡で蒸留する。その後、方策とツールセットを交互に更新する（model-tool co-evolution）。軌跡の評価に LLM の判定者を使う（"The trajectory-quality term R_traj employs an LLM-based judge to evaluate the soundness of the entire reasoning process"）。
- **評価**：CUB、Flowers、Cars、Pets、Aircraft で base-to-novel（"the names of the novel classes are never seen during training"）。データセットごとの学習と、5つを混ぜた学習の両方。4-shot の設定もある。
- **4.2 節の定義での判定**：
  - 局所の表現：部位を指定して得た計測値や画像を、全体とは別の証拠として推論に入れる → 当たる。
  - 局所の選び方：どの部位を測るかを、MLLM がサンプルごとに決める → サンプルごと。
  - 配分：ツールを呼ぶかどうか、どのツールをどの引数で呼ぶかを、学習した方策がサンプルごとに決める（"the model needs to decide which tool to invoke and how to set its arguments"）。閾値で局所を起動する HEF と同じ扱いで → サンプルごと。ただし、全体と局所の比を表す数値はなく、推論の中に暗黙に埋め込まれている。
- **B-1 に入る理由**：入力で上位カテゴリ（"This is an image containing a bird"）と候補の選択肢（"from the below options. {Boat tailed Grackle, Rusty Blackbird…}"）を与え、上位カテゴリ専用の部位ツール（`bird_color_histogram`、`bird_geometry`）を使う。手法の核が、上位カテゴリとカテゴリが所与の有限な集合であることを前提にしている。base-to-novel の novel も、同じデータセットの中の未知の種（鳥なら鳥）にとどまる。
- **新規性の置き方**：見るべき部位が分かった上で、外部ツールで測って具体的な判断基準（「尾は全長の約0.5」）を得ること。曖昧な印象（"its tail is not long"）に頼る既存の MLLM の推論を、検証できる証拠に基づくものにする。
- **提案手法との違い**：
  - 入力プロンプトで上位カテゴリを明示し、ツールも上位カテゴリ専用。
  - 局所の単位が、事前に作った「部位名つきの計測ツール」。見分けに効く属性と課題固有の知識からツールを作るので、部位の語彙（鳥の胸、翼、尾など）を前提にする。カテゴリをまたぐ意匠ベンチでは、そうした部位の語彙を事前に用意できない。
  - MLLM が見る局所の証拠は、主に計測値やヒストグラム。画像の領域そのものを選んで MLLM に見せ直す設計ではない。
  - 全体と局所の配分を表す明示的な変数がない。ツールを呼ぶかどうかの二値の判断が、推論の中に埋め込まれている。
  - 独自の教師 MLLM からの蒸留と、ツールセットの更新を含む事後学習が必要。ゼロショット版に相当するものはない。
- **本文と arXiv で確認できないこと**（PDF・HTML 版・TeX ソースのどれにも付録がない。TeX ソースの1行目は NeurIPS 2026 のテンプレートで、付録は投稿先にだけ出している可能性が高い）：
  - 属性を挙げるときの入力（クラス名か、学習用の画像か、データセット名か）。
  - ツールセットがデータセット（上位カテゴリ）ごとか、5つで共通か。
  - 部位の位置の特定方法（検出器、セグメンテーション、部位アノテーションなど）。
  - 学習するパラメータの範囲（全パラメータか LoRA か、画像エンコーダを固定するか）。本文にあるのは SFT のステップ数（データセットごとに2000、混合で2400、4-shot で200）と、H200 を使ったことだけ。

### 5.5 KFRA（CVPR 2026）：B-2・全体と局所・配分固定

- **論文**：Seeing as Experts Do: A Knowledge-Augmented Agent for Open-Set Fine-Grained Visual Understanding（Junhan Chen、arXiv 2603.03762）。事後学習しないエージェント。
- **仕組み**：
  1. Grounding-DINO の検出と Google Lens の Web 画像検索から、LMM がカテゴリの仮説を立てる。固定のカテゴリ一覧は使わない（"constructing a retrieval-augmented hypothesis space"）。
  2. 仮説ごとに Wikipedia から判別的な手がかり（例："red beak"）を引き、画像の局所に照合する。整合度が閾値に届かないときは、最も確信度の高い領域を超解像して照合し直す（"max_k s_{i,c}^{(k)} < τ"）。
  3. 全体の画像と証拠をまとめて LMM に渡す（"P(y|X, q) = F_lmm(X, q, {E_i})"）。
- **配分固定と判定する理由**：全体の画像と局所の証拠を並べて LMM に渡すだけで、両者の寄与の比を決める仕組みはない。閾値 τ が切り替えるのは局所の照合のやり直しで、配分ではない。
- **提案手法との違い**：
  - **局所の選び方が「名前の仮説と、その記述」に導かれる**（名前が分かれば探せる。DyFo と同じ向き）。本研究は、名前が分からない状態で手がかりの在り処を決める（探せれば名前が分かる）。
  - Web 画像検索に依存する。
  - 質問文 q を入力に取り、複数物体の画像も扱う広い「細粒度理解」の研究。自作ベンチ（FGExpertBench）は複数物体の画像を含み、除外1に近い性質もある。FGIC の6データセットの評価は多肢選択で、自由記述の採点はしていない。

### 5.6 関連研究での書き方

「全体と局所の配分と局所の選び方をサンプルごとに変える手法はある。推論に LLM を用いないもの（MGE-CNN、FG-MoE、HEF）は、配分を決めるゲートや閾値をテストと同じカテゴリのラベル付きデータで学習しており、学習したカテゴリしか扱えない（HEF はさらに上位クラスのラベルを前提にする）。推論に LLM を用いるものでは、ToolFG が、部位を名指しする計測ツールを MLLM に呼ばせて局所の証拠を集める。ただし、上位カテゴリを入力で明示し、その上位カテゴリ専用の部位ツールを使うので、上位カテゴリが違うカテゴリには対応できない。ToolFG が答えているのは「見るべき部位が分かった上で、どれだけ正確に判断するか」であり、本研究の「上位カテゴリも部位の語彙も分からない下で、どこを見るか」とは問いが違う。上位カテゴリやカテゴリの一覧を前提としない手法のうち、局所を使うのは KFRA だけである。KFRA は、Web 画像検索で立てた名前の仮説から手がかりを引き、それに合う局所を探して全体の画像と並べて LMM に渡す。局所の選び方は名前の仮説に導かれ、全体と局所の配分を決める仕組みはない。残りの手法は、すべて画像全体だけを入力する。」

## 6. B-2 の手法の核

| 手法 | 事後学習 | 問題意識 | 核 |
|---|---|---|---|
| Fine-R1 (ICLR 2026) | SFT＋強化学習 | 知識はあるのに使いこなせず、少数の例で学習すると既知のカテゴリに過学習する | 「見た目の分析 → 候補を挙げる → 比べる → 予測」の CoT で SFT し、TAPO（同じカテゴリの正例と軌跡を混ぜ、最も似た別カテゴリの負例とは答えが違ってくるように学習する強化学習）で仕上げる |
| DiVE-k (ICLR 2026) | 強化学習 | カテゴリ名の完全一致を報酬にすると、名前の暗記を招き、差分の推論が身につかない | モデル自身の K 回の答えの上位 k 個（最大5個）を選択肢にし、その中から正解を選ばせる強化学習。推論のときも、自分で選択肢を作ってから選ぶ |
| SpeciaRL (CVPR 2026) | 強化学習 | オープンワールドでは、正しいが一般的すぎる答え（「犬」）を返しがち。具体的に答えさせると誤りが増える | LLM の判定者で答えを6段階（W 間違い／A 答えない／G 一般的すぎる／S− 少し一般的／S 正解の粒度／S+ より具体的）に分け、N 回の答えの最良の段階を基準に、それ以上の答えにだけ報酬を与える。CUB の3000枚だけで学習し、別ドメインで評価 |
| VL-Taxon (arXiv 2026) | SFT＋GRPO（LoRA） | 大規模 VLM は、最も細かいレベルで正しくても中間の分類レベルを誤り、階層の一貫性を保てない | 界から種まで上から順に名前を書き出す2段階の階層推論。Stage 1 は候補なしで名前を生成する |
| SelfSynthX (ICLR 2025) | SFT（LoRA）＋棄却サンプリング | LMM は専門領域の分類が弱く、根拠を説明できない | 情報ボトルネックの考えで、クラスごとの概念リストから画像に合う視覚概念を選び、根拠つきの答えを自分で合成して反復的に学習する |
| KFRA (CVPR 2026) | なし（エージェント） | LMM の予測はパターン照合で、証拠の構築や知識による検証がない | Web 検索で仮説を立て、知識の手がかりで局所を照合し、全体と証拠をまとめて判断する（5.5 節） |

- **共通点**：KFRA 以外の5本は、MLLM（Qwen2.5-VL 系など）を事後学習して、答えの引き出し方や推論の仕方を改善する。画像全体だけを入力し、「どこを見るか」は扱わない。
- **意匠ベンチへの示唆**：SpeciaRL の6段階の評価は、自由記述の意匠ベンチの採点に使える（上位語に逃げる答えを G、答えないのを A として、間違い W と区別できる）。
- **プロンプトの上位カテゴリ名**：Fine-R1（公開コードの評価データは "Can you identify the bird in this image?"）、DiVE-k（"This is an image containing a bird"）、SelfSynthX（"What is the {item} in this image?"）は、プロンプトに上位カテゴリ名を入れる。SpeciaRL は "Classify the image." だけで、上位カテゴリ名を入れない。VL-Taxon のプロンプトは本文では未確認。

### 6.1 意匠ベンチの問題設定との適合

論文の本文と、公開コード（Fine-R1、DiVE-k、SpeciaRL）で確認した。

**確認の観点**

- **上位カテゴリ**：推論で上位カテゴリを与えずに動くか。
- **候補の一覧**：推論で候補やカテゴリの一覧を与えずに、自由記述で答えられるか。
- **上位カテゴリをまたぐ母集団**：上位カテゴリをまたいで形が似た物体が混ざるテストを想定しているか。
- **学習とテストの関係**：分布外・分布内・一部重なるの、どのシナリオで評価しているか。学習に要る注釈を意匠データで用意できるか。
- **採点**：自由記述の採点の仕方が意匠ベンチで使えるか。

**まとめ**

| 手法 | 上位カテゴリ | 候補の一覧 | 論文の学習とテストの関係 | 学習に要るもの | 論文の採点 | 意匠ベンチとの適合 |
|---|---|---|---|---|---|---|
| SpeciaRL | 与えない（"Classify the image."） | 与えない | **分布外**（鳥だけで学習し、花・食べ物・ペット・車・航空機でテスト） | カテゴリ名のラベル、学習中の LLM 判定者（Qwen3-30B） | LLM 判定者の6段階（Llama3-72B） | **そのまま合う** |
| Fine-R1 | 質問文に入れる（外せる） | 与えない（オープンワールドの評価） | 一部重なる（同じデータセットの中で、カテゴリの6割で学習し、残り4割でもテスト） | カテゴリ名のラベル、CoT データ（Qwen2.5-VL-32B で合成、1カテゴリ1枚） | 文字列の包含と、上位カテゴリ名を基準にした SigLIP の相対類似度 | 手直しすれば合う |
| DiVE-k | 質問文に入れる（外せる） | **評価では1段目に評価分割のカテゴリ一覧を入れる** | 一部重なる（同じデータセットの中で、カテゴリを半分に分ける） | カテゴリ名のラベル | LLM 判定者（同じ細かいカテゴリか） | 一覧なしの数値がない。数千カテゴリから選ぶ形式なら合う |
| VL-Taxon | 与えない（界から上から順に自分で決める） | Stage 1 は与えない。主な評価は各レベル4択 | **分布外**（植物で学習し、動物と鳥でテスト） | **各レベルに名前の付いた分類階層** | 階層の一貫性（HCA）と葉の正解率。自由記述の評価は付録の1表だけ | 階層を用意できれば合う。上から順に決める仕組みが、ベンチの難しさとぶつかる |
| SelfSynthX | 質問文に入れる（外せる） | 与えない | **分布内のみ**（学習と評価が同じクラス集合） | カテゴリ名のラベル、クラスごとの概念リスト（LLM で作れる） | 正解の名前が回答に含まれるか | 分布内のシナリオだけ |
| KFRA | 与えない | 与えない（Web 画像検索で仮説を立てる） | 学習しない | なし（Google Lens、Wikipedia） | 多肢選択のみ | **そのままでは使えない**（Web 画像検索が特許図面そのものを引き当てるおそれ）。外部ツールに頼るので、End-to-End の方針でベースラインから外す |

**手法ごとの詳細**

- **SpeciaRL**（最も合う）
  - プロンプトは "Classify the image." だけで、上位カテゴリも候補も与えない。意匠ベンチの設定と同じ。
  - 分布外での評価が主な設定（"training and testing data are from different domains. All evaluations are therefore conducted in an out-of-domain setting"）。付録に、学習データのドメイン・規模・混合を変えた実験もある。
  - 採点の6段階（W／A／G／S−／S／S+）は、判定者のプロンプトに "product line" の例があり、製品名の粒度のずれ（「椅子」と「オフィスチェア」）もそのまま扱える。
  - **注意**：新しい知識を入れる手法ではない（"we do not aim to inject new knowledge into the model, but rather, we seek to improve its sampling efficiency"）。64回答えさせた最良の答え（BoN-64）でも当たらない問題は改善しない。線画でベースのモデルが知識を引き出せないなら、効果は小さい。
  - 計算資源：A100 を6枚（学習に4枚、判定者に2枚）。コードは公開（github.com/s-angheben/SpeciaRL）。
- **Fine-R1**（手直しすれば合う）
  - 質問文に上位カテゴリ名が入る（"Can you identify the bird in this image?"）が、一語なので外せる。オープンワールドの評価では候補を与えない。
  - **学習の CoT が、同じ上位カテゴリの中で比べるように作られている**。CoT データを作るプロンプトは "This is a picture of a {label} … provide at most four candidate subcategories of the same super-category"。上位カテゴリをまたいで候補を比べる推論は学習しない。意匠ベンチで学習するなら、"of the same super-category" を外して CoT を作り直す必要がある。
  - 一方、強化学習（TAPO）の負例は「見た目が最も似た別のカテゴリ」（"a negative image xneg from the most visually similar but distinct subcategory"）。意匠ベンチで上位カテゴリをまたぐ形の似た負例を選べば、ベンチの難しさにそのまま合う。
  - **採点に上位カテゴリ名を使う**。オープンワールドの類似度は、上位カテゴリ名（公開コードでは画像のパスから "bird" などを決める）と正解の類似度を基準にした相対値。意匠ベンチでは上位カテゴリが未知なので、この採点は使えない（文字列の包含は使える）。
  - 論文の unseen は、同じデータセットの中の未知カテゴリ（上位カテゴリは学習と同じ）。分布外は評価していない。
  - 計算資源：A6000 を4枚。コードは公開（github.com/PKU-ICST-MIPL/FineR1_ICLR2026。本文の URL とは名前が違う）。
- **DiVE-k**（一覧なしの数値がない）
  - **論文の数値は、1段目のプロンプトに評価分割のカテゴリ一覧を入れて出している**。付録の図7は "The species name of the bird strictly belongs to below category list {category list}"。公開コードの評価スクリプトも `use_cat_list="True"` で、novel の評価では novel のカテゴリの一覧（CUB なら100種）を入れる。学習の選択肢づくりでも base のカテゴリの一覧を入れる。
  - 一覧を外すオプションはコードにある（`use_cat_list` を False にすると質問文だけになる）。ただし、その設定の数値は論文にない。
  - **ベースのモデルが自分の上位 k 個に正解を含められることが前提**（"the method's efficacy is contingent on this baseline performance"）。論文では1段目の上位 k 個に正解が入る率が約9割だった。線画でこの率が低ければ、2段目で選ぶ余地がない。
  - MTG で出た「数千の全カテゴリから選ぶ」形式なら、DiVE-k の一覧つきの設定がそのまま当てはまる。ただし、数千の製品名をプロンプトに入れる長さの問題がある。
  - 計算資源：A6000 を3枚。コードは公開（github.com/raja-kumar/DiVE-k）。
- **VL-Taxon**（階層を用意できれば合う）
  - 学習に、各レベルに名前の付いた分類階層が要る（iNat21-Plant の界・門・綱・目・科・属・種）。意匠データなら、ロカルノ分類（大分類 → 小分類 → 製品名）で代用できる可能性がある。ただし、論文は ImageNet（WordNet の階層）を「各レベルの名前と定義がなく、選択肢の意味が重なる」という理由で評価から外しており、製品の階層にも同じ問題が起こりうる。
  - **上から順に決める仕組みが、ベンチの難しさとぶつかる**。上位のレベルを先に決め、それを条件に下位を決めるので、上位カテゴリをまたいで形が似た物体では、最初の段の誤りがそのまま伝わる。論文自身も、植物だけで SFT すると必ず Plantae から書き始め、動物を植物と誤ると報告している（強化学習で緩和）。
  - 主な評価は各レベル4択。自由記述（open-set）の評価は付録の表7だけ（iNat21-Animal で葉の正解率 30.74%）。
  - 分布外（植物 → 動物）で評価している。コードは本文に記載なし。
- **SelfSynthX**（分布内のシナリオだけ）
  - 学習と評価が同じクラス集合で、未知のカテゴリでの評価はない。クラス名を学習で覚える作りなので、分布外のシナリオで効く根拠はない。
  - 学習に、クラスごとの概念リストが要る（LLM で作れる）。製品名に対して LLM が挙げる概念は、見た目より機能になりやすい。
  - ベースは LLaVA-1.5-7B で、H100 を8枚。コードは公開（github.com/sycny/SelfSynthX）。
- **KFRA**（そのままでは使えない。End-to-End の方針でベースラインから外した）
  - 外部ツール（Google Lens の Web 画像検索、Wikipedia）に頼るエージェントで、End-to-End で解く提案手法とは比べる土台が違う（2026-10-02 決定）。
  - 仮説を Google Lens の Web 画像検索で立てる。特許図面は Google Patents などで公開されているので、検索が同じ特許の図面を引き当て、タイトル（正解）が漏れるおそれが高い。特許のサイトを検索から除けば、手法の核が弱まる。
  - Wikipedia の手がかりは、製品名に対しては機能の説明が中心になり、形の手がかりが取れるかは分からない。
  - FGIC の評価は多肢選択だけ。コードの公開は確認できない。商用の検索 API に依存し、再現性が低い。

**自由記述で出力できるか**

6本とも、仕組みの上では自由記述で名前を出せる。論文で自由記述のまま評価したかは分かれる。

| 手法 | 自由記述で出せるか | 最終出力の形 | 論文の自由記述の評価 |
|---|---|---|---|
| SpeciaRL | 出せる（本来の形） | `<answer>` に名前1つ、または答えない（None） | ある（主な評価） |
| Fine-R1 | 出せる（本来の形） | `<answer>` に名前1つ。学習もオープンワールドの形だけで行う（"trained solely on open-world FGVR tasks"） | ある（オープンワールドの評価） |
| DiVE-k | 出せる（一覧を外せば） | 1段目で20回自由に答え、多い順の上位5個を選択肢にし、2段目で記号を選ぶ。記号を名前に戻すので、最終出力は自分が1段目で書いた名前のどれか | ない（論文の数値は1段目に一覧あり） |
| VL-Taxon | 出せる（Stage 1 の出力） | Stage 1 で、界から種まで書き出して最も細かい名前を答える。Stage 2 は各レベルの選択肢が要る | 付録の表7だけ（iNat21-Animal） |
| SelfSynthX | 出せる | 「この鳥は〜です。根拠は〜」という説明文の中に名前が入る。`<answer>` の区切りがないので、名前を文から取り出す必要がある | ある（正解の名前が回答に含まれるかで採点） |
| KFRA | 出せる（質問文次第） | 最後の LMM が質問文 q に答える。「これは何か」と聞けば自由記述になる | ない（FGIC も FGExpertBench も多肢選択） |

- **DiVE-k を自由記述で使うときの注意**：1段目の答えの数え方は、小文字化と記号の除去をした後の文字列の完全一致（`clean_string`）。言い換え（"coffee maker" と "coffeemaker"、"chair" と "office chair"）は別の候補として数えられ、票が割れる。製品名はこの揺れが大きいので、上位5個が同じ製品の言い換えで埋まるおそれがある。
- **SelfSynthX と VL-Taxon は、学習した名前に寄りやすい**：SelfSynthX は学習と評価が同じクラス集合で、クラス名を覚える作り。VL-Taxon の Stage 1 の報酬は正解の名前との完全一致。どちらも、学習にないカテゴリを自由記述で答えられるかの根拠は少ない（VL-Taxon の付録の表7だけ）。

**6本に共通すること**

- **テストは全部「1データセット＝1上位カテゴリ」ごと。** 複数のデータセットを混ぜて学習する設定（DiVE-k、SpeciaRL の付録）はあっても、テストに上位カテゴリをまたいで紛らわしい組はない。ベンチの新規性の裏づけになる。
- **分布外で評価しているのは SpeciaRL と VL-Taxon だけ。** Fine-R1 と DiVE-k は同じデータセットの中の未知カテゴリ（一部重なる）、SelfSynthX は分布内だけ。
- **SpeciaRL と DiVE-k は、ベースのモデルが何度か答えれば正解を出せることを前提にする**（BoN、上位 k 個）。線画でこの前提が崩れるかは、ベースのモデルで先に測れる。
- **意匠ベンチのベースラインの優先順位**：SpeciaRL（そのまま）→ Fine-R1（プロンプトと CoT の手直し）→ DiVE-k（一覧なしと、数千の一覧ありの両方）→ VL-Taxon（ロカルノ分類で階層を作れる場合）。SelfSynthX は分布内のシナリオだけ。KFRA は外す（外部ツールに頼るため。End-to-End の方針、2026-10-02）。

## 7. 局所をサンプルごとに選ぶ最も近い A の手法：LAGO（arXiv 2026、CLIP の埋め込みの類似度で分類）

- **FGVC の文脈**："global alignment is often insufficient for fine-grained recognition, where decisive evidence may lie in localized object parts, attributes, or textures rather than in the image as a whole"
- **局所の選び方**：クラスに依存しない物体中心の候補（FastSAM）を出し、その後、中間の確信度に応じた強さでテキスト誘導して絞り込む。サンプルごとに変わる。
- **配分**：`z_dc = α_dc z_o + (1−α_dc) z_c`、`z_final = λ z_dc + (1−λ) z_full`。"We optionally calibrate the fusion weights (β, α_dc, λ) per dataset"。つまり、データセットごとに固定。
- **実験**：LAGO の λ を固定したままのものと、提案手法（λ をサンプルごとに決める）を比べれば、配分を適応させる効果を直接示せる。
- **注意**：査読前の arXiv 論文。評価には、ImageNet、DTD、Places など細粒度でないデータセットも含む。

- **論文での言い方**：2章の1の文。
- **要検証**：iNat で上位カテゴリをまたぐ誤りが少ないことは、推論にとどまる。上位カテゴリ単位の正解率を報告した論文を探すか、既存モデルの誤りの内訳を自分で測る。

### 8.3 自由記述の採点の参考になるベンチ・分析

PDF は `論文/論文PDF/自由記述の評価の参考になるベンチ・分析/`。

- **On Large Multimodal Models as Open-World Image Classifiers**（Conti、ICCV 2025）：自由記述を LLM と埋め込みの類似度で採点し、予測を具体的／一般的、正しい／間違いに分ける。SpeciaRL の6段階の土台。
- **FIKA-Bench**（arXiv 2605.13193）：外部検索を前提にした自由記述の細粒度認識。最良のシステムでも25.1%。
- **GranFact**（arXiv 2606.29573）：自由記述の応答を実体に分解し、粗から細の正解階層に割り当てて、正しさと具体性を分けて測る（複数物体向け）。
- **Finer**（EMNLP 2024）：正解の文字列が最初の20トークン以内にあれば正解とする、ゆるい完全一致。
- **Your "Flamingo" is My "Bird": Fine-Grained, or Not**（Chang、CVPR 2021）：1つの答えではなく、事前に決めた分類階層を上から下へたどる複数の名前を出す設定を提案（A-1 系、上位カテゴリは1つ）。CUB での50人の人間調査で、1つの名前だけを好んだ回答は36.4%で、専門家でも約8割が粒度の違う複数の名前を望んだ。「上位語に逃げる答えを不正解にして良いか」という論点の根拠になる。
- **Why are Visually-Grounded Language Models Bad at Image Classification?**（NeurIPS 2024）：含有判定で採点。MLLM の分類の弱さは、学習データでのクラスの出現頻度と強く相関すると報告。
- **FishNet++**（arXiv 2509.25564）：35,133種の記述を使う開放語彙の認識。
- **Is CLIP the Main Roadblock for Fine-Grained Open-World Perception?**（Bianchi、arXiv 2404.03539）：CLIP の埋め込みでは細かい属性が分離しにくいことを示す。

2. **自由記述の意匠ベンチの採点を決める。**
   - 採点の方法：同義語や粒度のずれ（"Coffee Maker" と "Coffeemaker"、"Chair" と "Office chair"）の扱い。CaSED の指標（Semantic Similarity、Semantic IoU）、Conti et al. の指標、LLM による判定が候補。
   - 上位語に逃げる答え（「椅子」ではなく「家具」）の扱い。有力な候補は SpeciaRL の6段階の評価（LLM の判定者で W／A／G／S−／S／S+ に分ける。6章）。
   - 評価の形式（自由記述か、数千の全カテゴリからの選択か）は、製品名（カテゴリ）間の類似度を計算し、正解と認める類似度の線が引けるかを見てから決める。
   - B-1 と A の手法（候補の一覧を前提とする）との比較の設定。
3. **ベンチマークを精査し、形の細部を見て初めて製品名が分かるものに限定する。** 想定される査読の指摘「線画だから分かりにくいだけで、実画像なら分かる」に答えるため。
   - **周りの状況**：頼らない設定にする。周りの状況に頼らずに推定できるほうが良い、と主張する。
   - **大きさ**：分からない設定にする。比較できる物体がない、絶対的な長さが分からない、物体によって大きさがいろいろな値を取りうる、という理由。
   - **色・材質**：画像から取り除く設定にはしない（現実では見えるので無理がある）。代わりに、色・材質があれば製品名が分かる問題をベンチから取り除く。
   - **除き方**：人手のアノテーションは使わない。案として、正解と誤答の候補の組ごとに、LLM に「この2つの製品は色や材質だけで見分けられるか」を判定させる。
   - **形状が似ているものを固める**：形状が似ている図面の集合の中で、製品名の意味の散らばりを確認する。
   - **誤答例での見立て**：色・材質で解けそうな組（ペットフィーダーとチーズボード、カメラとアダプターのキャップなど）は除く対象。形も材質も似ていて写真でも紛れる組（テーブルとカート、フックとブラケット、角丸の樹脂筐体どうし）は残る。
   - **補強の実験**：描き方（線画／写真）× 設定（1つの上位カテゴリの中／上位カテゴリをまたぐ）の 2×2。写真でも上位カテゴリをまたぐ設定の誤答が多く残れば、難しさは描き方ではなく設定から来ると言える。3D モデルのある商品データ（例：Amazon Berkeley Objects、要確認）から線画と写真調を両方描けば、同じ物体で描き方だけを変えて比べられる。
   - **今のデータで言えること**：描き方は全問で同じなのに、誤答率はありふれ度で43.6%から70.8%まで変わる。線画でも輪郭が特徴的なもの（シューズ、パーカー、櫛など）は当たる。
