# Qwen-VL等マルチモーダル埋め込みモデルを基盤とするドメイン特化事後学習の最新動向サーベイ

## 1. VLM埋め込みモデルの台頭とドメイン適応における技術的ボトルネック

### 1.1 デコーダー型VLMベース埋め込みモデルの優位性

CLIPに代表される従来のデュアルエンコーダ（二重エンコーダ）モデルは、ゼロショット性能において一時代を築いたものの、テキストエンコーダの表現力や語彙能力、画像内の空間的・トポロジー的構造を正確に捉える能力（袋小路効果やテクスチャバイアス）に決定的な制約を抱えていました。

これに対し、近年では大規模マルチモーダル言語モデル（MLLM / VLM）のテキストデコーダと言語モデルの強力な統合表現力をそのままベクトル検索空間にアラインメントする、デコーダー型VLM埋め込み（例：Qwen3-VL-EmbeddingシリーズやVLM2Vec）が事実上のデファクトスタンダードとなっています。

これらのモデルは、画像、長文テキスト、構造化ドキュメントなどのマルチモーダル入力を単一のマニフォールド（共通埋め込み空間）上に高密度にエンコードし、Matryoshka Representation Learning（MRL）による次元削減への柔軟な対応や、数万トークンに及ぶ文脈理解をサポートします。

### 1.2 ドメイン適応（事後学習）の不可欠性

しかし、事前学習済みの汎用VLM埋め込みモデルをそのままゼロショットで適用する場合、専門性の高いニッチなドメイン（実用的な意匠、幾何学的設計、防衛/特許等の専門出版物など）においては、性能の頭打ちが発生します。

工業図面や意匠、チャート等は、一般的な自然画像と比べて色や背景のテクスチャ情報が完全に消失しており、極めて厳密なレイアウト、接続関係、微小なアトリビュートの差異（円弧や境界線の接続数など）が意味を決定づけるためです。

したがって、すでに基礎的な位置整合（M-RoPEなどによる空間理解）や基本アラインメントを身につけている既存のマルチモーダル埋め込みモデルを出発点とし、特定のドメインデータに適応させるための「事後学習（Post-training / Fine-tuning）」が必須となっています。

## 2. PEFT (LoRA) / アダプターを用いた事後学習アーキテクチャ

既存のVLM埋め込みモデルの一般知識や基礎となるモーダル整合空間を崩さずに、特定の意匠や図面レイアウト、あるいはドメイン固有の表現形式を認識させるためには、パラメータ効率的微調整（PEFT）が極めて有効です。代表的な事後学習アーキテクチャおよびパラメータ構成は以下の通りに体系化されています。

### 2.1 Qwen-VLベースの推奨LoRA構成

Qwen系VLM（特に Qwen3-VL-Embedding シリーズ）をファインチューニングする場合、単にSelf-Attentionレイヤーのみを対象にするのではなく、マルチモーダル情報の射影・再アラインメントを可能にするために、言語デコーダ側のMLP（FFN）層を含む、ほぼすべての線形投影レイヤーをLoRAのターゲットとすることが強く推奨されます。

- **ターゲットモジュール (Target Modules)**: `q_proj`, `v_proj`, `k_proj`, `up_proj`, `down_proj`, `gate_proj` [cite: 12]
- **LoRAハイパーパラメータ**: ランク $r = 32$、スケーリング係数 $\alpha = 32$。より高い複雑度や幾何バインディングが必要な場合は $r = 64, \alpha = 128$ の設定も用いられます。

### 2.2 LCO-Emb (Language-Centric Omnimodal Embedding)

XiaoらによるNeurIPS 2025の発表（LCO-Emb）では、事後学習時における「言語中心的コントラスティブ学習（Language-Centric CL）」の決定的な理論が示されました。

VLM（MLLM）は生成学習の段階で、すでに内部表現空間に「暗黙的なクロスモーダル・アラインメント」を完了させています。そのため、ドメイン特化時に画像データが不足している場合であっても、LoRAを用いてテキストペアのみの対照学習（例：専門ドメインの技術記述や用語アライメント）を行うだけで、異方性（Anisotropy）の崩壊を防ぎながら、画像などの他モーダルの表現空間も引きずられる形で高精度に整列（アライメント）します。

この「Generativeな能力の高さが埋め込み潜在力の強さを決定づける」とするGeneration-Representation Scaling Law（GRSL）は、軽量なドメイン適応における極めて強力な指針となっています。

### 2.3 最新のマルチアダプター・サイドアーキテクチャ

**Dual-LoRA (TWN: Think When Needed)**：フローズン状態のVLMバックボーンを共有しながら、「段階的思考プロセス用のReasoning Adapter」と「埋め込み表現形成用のEmbedding Adapter」を独立して配置し、各アダプターのインターフェースで勾配を遮断（デタッチ）するアーキテクチャです。これにより、意味解釈（LLMの思考）の勾配干渉を防ぎつつ、単一モデルで判別埋め込みを最適化できます。

**Side-Adapter / Stresa**：バックボーンの最終レイヤーの表現（シングルベクトル）に過度な情報圧縮を依存させると、画像内の局所的な幾何要素（微細な意匠、記号など）が埋没します。そこで、凍結した Qwen3-VL-8B-Embedding などの各中間層の隠れ状態（hidden states）を「Stresa」などの軽量サイド・アダプターへと横から引き出し、複数のスケールから特徴マップを構築することで、高密度かつ高精度の幾何表現を担保する設計が有望視されています。

## 3. プーリング戦略とアテンション構造の比較検証

自己回帰（デコーダー型）VLMを埋め込みベクトルに変換、あるいは微調整する際には、「どのトークンの状態を埋め込みベクトルの表現とするか」のプーリング戦略がモデルの局所空間認知能力を支配します。

### 3.1 3大プーリングアプローチの比較

既存の主要文献において議論されている主要な埋め込み抽出方法は以下の通りです。

| プーリング手法 | メカニズム | 特徴 |
| --- | --- | --- |
| 暗黙的プーリング (EOS / EOT Pooling) | 入力の最後尾に配置される `<EOS>` または `<EOT>` トークンの最終レイヤー隠れ状態を抽出 | Qwen3-VL-Embedding のデフォルトのvLLMポーリングランナーなどで標準サポートされており、実装が極めて容易。しかし、因果的アテンション（Causal Mask）を適用したままでファインチューニングを行うと、シーケンス前方の局所幾何情報や視覚アトリビュートが `<EOS>` へ十分に圧縮されないボトルネックが生じやすくなる |
| 平均プーリング (Mean Pooling) | 言語モデルの因果マスクを完全に解放し、双方向アテンション（Bidirectional Attention）に変更した上で、全てのテキスト・視覚トークンの最終層ベクトルの平均値を算出 | ドキュメント理解やチャートの特定（Jina Embeddings V4など）において高い安定性を示すが、微細なアトリビュートの差異が平均化によって打ち消されるリスクもある |
| 明示的プーリング (Bottleneck Tokens / Query Tokens) | 学習可能な数個〜数十個（例：$K=16$）のQueryトークン（BToks）をアテンションシーケンスに挿入し、これらのトークンに対してのみ全コンテキストへのアクセスを許容するアテンション制約（Condensation Mask）を適用 | 情報のショートカットを防ぎ、次のトークン予測や復元に必要な「幾何・空間情報の全要素」をBToksに強制的に凝縮させるため、最も表現の密度が高くなる |

## 4. 対照学習・損失設計とハードネガティブ構築の実装事例

手元に存在する「類似図面ペア」や「意匠とメタデータのペア」をコントラスティブ学習で適応させる際、CLIPのような一からの学習ではなく、すでに学習済みのVLM空間をマニアックな製品へと正確にアラインメントするための損失設計が数多く実装されています。

### 4.1 SentenceTransformersを用いたMRL適応

Qwen3-VL-Embedding-2Bのような現代的な埋め込みモデルをファインチューニングする際の、標準的な最適化の組み合わせは `CachedMultipleNegativesRankingLoss` を `MatryoshkaLoss` で包み込む手法です。

```python
from sentence_transformers.losses import CachedMultipleNegativesRankingLoss, MatryoshkaLoss

# GPUメモリを抑えながら巨大な仮想バッチで対照学習を安定化
base_loss = CachedMultipleNegativesRankingLoss(model, mini_batch_size=1)

# MRLを崩さずに事後学習を適用（多様なベクトルサイズをサポート）
loss = MatryoshkaLoss(
    model,
    base_loss,
    matryoshka_dims=[2048, 1536, 1024, 512, 256, 128, 64]
)
```

この設計により、メモリ空間を節約しつつ（Flash Attention 2 / bfloat16を活用）、高精度なインバッチネガティブ対照学習を実行できます。

### 4.2 ハードネガティブTripletによる検索精度の変革

意匠検索において最も重要となるのが、一般的な製品から見れば単なるノイズにしか見えない「細部の違いが異なる類似製品」を確実に落とす ハードネガティブ（Hard Negative） の設計です。データセットを `(anchor, positive, hard_negative)` の三つ組（Triplet）として定義し学習を課します。

**実証事例**：Qwen3-VL-Embedding-2B をベースに、ドメイン固有の図表・レイアウトを含むマルチモーダルペアデータセットに対し、明示的に1つのHard Negativeを指定したSentenceTransformersでの事後学習（Qwen3-VL-Embedding-2B-vdr）を施したところ、わずか数千枚のデータからなる学習でありながら、検証セットにおける検索指標 NDCG@10が **0.888 から 0.947** へと大幅に向上しました。

### 4.3 複数段階のアライメント（Multi-Stage Alignment）

eコマースをはじめとする視覚的製品検索のドメイン適応研究（Beyond Text）では、すべての適応を1パスで終わらせようとするとモデルが混同を起こしやすいことが指摘されています。これに対し、以下のステージを段階的に踏む カリキュラム・アライメント が有効です。

- **Stage 1: ドメイン継続学習（Domain Adaptation）**：数百万枚規模の「ドメイン名・仕様テキスト - 意匠画像」のペアを用い、全体としてのドメイン基礎表現空間のミスマッチを解消する。
- **Stage 2: モダリティ固有クエリアライメント（Query Alignment）**：ユーザーが実際に入力する「不完全なラフスケッチ、あるいは部分的なテキスト文」と、目的の製品画像（またはCAD図面）を明示的に整列させ、ユーザーのインテントとアイテム表現間のマッピングを急激に収束させる。

### 4.4 生成器に整合させる損失設計 (LVLM-Aware Retrieval Loss)

マルチモーダルRAGのように、検索された意匠情報を最終的に別の生成モデル（例：Qwen3-VL等）に処理させる下流システムを構築する場合、「LVLM-Aware Retrieval Loss」が極めて効果的です。

検索埋め込みのコントラスティブ損失のみを追及すると、検索モデルが類似度判定したものが、回答生成モデル（Reader）にとって有益とは限らないミスマッチが発生します。これを防ぐため、回答生成VLMが正しいクラスラベルや判断を出力できたときの予測確率（LVLMクラス限定事後確率分布 $p_{\text{LVLM}}$）を「教師シグナル」とします[1]。そして、埋め込み検索モデル（Retriever）が計算する類似度分布 $p_{\text{RETR}}$ との間の KLダイバージェンス損失（$\text{KL}(p_{\text{LVLM}} \parallel p_{\text{RETR}})$）を算出して逆伝播させます[1]。

この軽量な事後学習を介すだけで、下流のVLM生成器に最も適合するような「正しく論理を導ける図面」が優先的に検索表現空間の上位に引き上げられるようになります[1]。

## 5. 実運用向けの優先度付き実装ロードマップ

手元にある独自の意匠データ、形状データを用いて Qwen-VL の埋め込みモデル（例: Qwen3-VL-Embedding-2B / 8B）を最適に事後学習させるための、推奨される優先度付き実装ステップを以下に定義します。

### ロードマップ全体像

```text
Phase 1: 環境のセットアップとLoRA-CachedMNRLによるベースライン構築（高優先）
  ↓
Phase 2: ドメイン特化Tripletデータ構築とMatryoshkaLossの導入（中優先）
  ↓
Phase 3: 二段階アライメントの適用（ドメイン適応 → クエリアライメント）
  ↓
Phase 4: 下流生成VLM（RAG等）と統合したLVLM-Aware KLアライメント（発展）
```

### Phase 1: 【高優先】SentenceTransformersを用いたLoRA＋CachedMNRLの構築

**モデル読み込みの設定**：Qwen3-VL-Embedding-2B をベースモデルとし、GPUメモリ削減と実行効率最大化のために `attn_implementation="flash_attention_2"`, `torch_dtype="bfloat16"` を指定。また、画像の最大入力画素を `max_pixels=600*600` などに制限し、バッチサイズ引き上げのためのGPUリソースを確保する。

**LoRAの適用**：PEFTライブラリを使用し、バックボーンLLMの `q_proj`, `v_proj`, `k_proj`, `up_proj`, `down_proj`, `gate_proj` をターゲットにLoRA（$r=32, \alpha=32$）を設定。

**ベースライン訓練**：手元にある「同一意匠の別アングル」「意匠画像と製品ラベルテキスト」のペアを用いて、`CachedMultipleNegativesRankingLoss` を通じたファインチューニングを実行。

### Phase 2: ドメイン特化Tripletデータ構築とMatryoshkaLossの導入

**ハードネガティブマイニングの実施**：独自の意匠・図面データにおいて、「形状的には極めて似ているが、細部の特徴（アトリビュート）や規格が異なる」ものをネガティブ例（Hard Negative）として抽出、またはテキスト記述の微小なカウンターファクチュアル変化（CF-VLM）を記述したペアを構築。

**triplet 形式のデータ構成**：`(anchor, positive, hard_negative)` の形式にアノテーションを完全に標準化し、SentenceTransformersの入力フォーマットとしてローディング。

**多次元ベクトルの保持（MRL）**：MatryoshkaLoss で対照損失をラップし、実環境への配慮（256次元や512次元へのインデックス最適化）を行ってもコサイン類似度検索の性能が崩壊しない適応空間を形成する。

### Phase 3: 複数段階アライメント（ドメイン適応 ➔ クエリアライメント）の実践

**ドメイン特化（Stage I）**：まずは「製品名・設計仕様書 - 意匠図面」の膨大なペアデータから対照学習を開始し、Qwenの言語表現と独自の工業用線画表現を大まかに統合アラインメントする。

**意図適合（Stage II）**：ユーザーの不完全な「ラフ手描き線画、あるいは検索入力プロンプト」をアンカーとし、Stage I で整列した「完成版図面」を引き当てるための、よりタスクに特化したLoRA適合チューニングを実行する。

### Phase 4: 【発展】下流タスク（RAG等）と連動した強化学習・LVLM-Aware最適化

**回答予測確率の抽出**：検索された類似意匠・図面を用いて、下流のVLM（例：Qwen3-VL-8B-Instruct 等）に仕様判定や自動起草を行わせた際、正しい解答を出力できる確率分布（LVLM posterior）をログとして算出・保存。

**KLダイバージェンス最適化**：Retriever側のコサイン類似度（予測確率）と、上記LVLM posteriorが合致するようにKLアライメント損失を用いて事後学習を実行し、回答精度のハルシネーションを極限まで打ち消した統合幾何検索エンジンへと昇華させる。
